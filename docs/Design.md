# DupeSeek 设计文档

## 架构

* 标准的 electron + vue3 + typescript 架构，前端使用 vue3 进行界面开发，后端使用 electron 进行文件系统操作和重复文件识别。
* 前端和后端通过 IPC（进程间通信）进行数据交换，确保界面响应迅速，同时能够处理大量文件的扫描和识别任务。
* 综合使用 文件名 + 文件大小 + 前1MB md5 + 全文件 md5 + 全量 CRC32 进行重复文件识别，以实现速度和准确性的平衡。CRC32 用于快速比较压缩包内文件而无需解压，md5 用于更准确的重复文件识别。
* 前端使用 virtual list 技术来高效地展示大量文件信息，确保界面流畅。
* 前端使用 pinia 进行状态管理，确保应用状态的一致性和可维护性。
* 前端的 layout 组件和 UI 功能组件分离，确保代码的模块化和可复用性。
* 后端使用多线程或异步处理来加速文件扫描和哈希计算，避免界面卡顿。
* 后端使用 sqlite 数据库来存储扫描结果和用户设置，确保数据的持久化和下次的快速访问。

## UI

* 整个 electron 窗体有最小长宽限制，确保界面元素的正常显示。
* 主界面分为顶部的全局功能设置栏（Settings），下左侧的 '操作目标列表 (TargetList)' 和右侧的 '多 tab 操作切换区'，右侧通过 tab 切换不同的操作和功能界面。Tab 在顶部，下方是对应的功能界面。
  * Tab1: '硬盘、目录与文件列表'，用于向 TargetList 添加操作目标。
  * Tab2: '重复文件扫描设置'，用于配置重复文件扫描的相关参数，并启动扫描过程。
  * Tab3: '重复文件列表'，用于显示扫描结果。
  * Tab4: 'Treesize 可视化'，用于展示磁盘空间使用情况和重复文件分布。
* 窗体没有菜单栏，所有功能通过界面上的按钮和选项进行操作。

## 组件与功能设计

### Layout 组件

* 负责整体界面的布局和结构，layout 组件应当与各个功能组件分别编写。layout 组件不应该包含任何具体的功能实现。
* 除 mainwindow.vue 以外，其它 layout 组件均为实际具体布局方式的组件，并且以其布局方式命名，带 Layout 前缀。例如：'HorizontalLayout.vue'、'VerticalLayout.vue' 等。类似于 bootstrap 的栅格系统，提供不同的布局方式供功能组件使用。

### 界面布局简述

* MainWindow.vue 作为全局主界面，拥有不可见的上中下三层布局结构。
  * 上层 用于容纳全局功能设置的各按钮，目前仅包含最右侧一个“设置”齿轮图标和对应文字。高度为固定值。
  * 中层 布局为主体空间，宽度和高度都跟随窗口变化。中层布局内继续容纳一个水平布局子组件，分为左右两部分。
    * 包含一个水平布局组件 horizontal-layout.vue。
    * 左侧固定宽度，用于显示 TargetList 组件，显示用户选择的操作目标列表。
    * 右侧占满剩余空间，用于显示 tab 切换组件和对应的功能界面组件。
      * 内部包含一个 vertical-layout.vue 垂直布局组件。
      * 上部固定高度，用于容纳 tab 切换组件 (tabs.md)，用户可以通过点击不同的 tab 来切换右侧功能界面。
      * 下部占满剩余空间，用于容纳对应的功能界面组件，根据当前选中的 tab 来切换显示不同的功能界面组件。
  * 下层为固定高度的状态栏，显示操作状态和提示信息。
  * 布局组件不包含任何具体的功能实现，所有功能逻辑都应当在对应的功能组件中实现。布局组件也不应该直接调用功能组件的函数或方法，程序通过事件或状态管理来实现组件之间的通信和数据传递。

### 功能组件详细说明文档链接

- [ScanSettings.md](./ScanSettings.md)：用于配置重复文件扫描的相关参数，例如文件类型过滤器、是否包含隐藏文件等。
- [DuplicateList.md](./DuplicateList.md)：用于显示扫描结果中的重复文件列表，支持查看文件详细信息和进行重复文件处理操作。
- [TreeSizeVisualization.md](./TreeSizeVisualization.md)：用于展示磁盘空间使用情况和重复文件分布，帮助用户更直观地了解磁盘空间的使用情况。
- [Tabs.md](./tabs.md)：用于实现不同功能界面的 tab 切换逻辑和界面设计。
- [Settings.md](./Settings.md)：用于配置应用的全局设置。
